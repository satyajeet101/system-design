# Scenario based Interview Questions

1. - [ ] API latency suddenly increases after deployment. What do you check first?

2. - [ ] Database connection pool gets exhausted. What could be the reason?

3. - [ ] API works locally but becomes slow in production. How do you debug it?

4. - [ ] A Spring Boot service starts returning random 500 errors. Where do you begin?

5. - [ ] Memory usage keeps increasing until the application crashes. How do you find the root cause?

6. - [ ] One downstream service becomes slow and affects your entire API. How would you isolate the impact?

7. - [ ] Multiple users update the same record simultaneously. How do you prevent inconsistent data?

8. - [ ] Cache improves performance but starts serving stale data. How would you fix it?

9. - [ ] Your scheduled job executes multiple times after deploying multiple instances. Why?

10. - [ ] Application is healthy, but users are still getting timeouts. What would you investigate?

11. - [ ] API response is slow even though the database query is fast. Where else could the bottleneck be?

12. - [ ] Logs are available across services, but tracing one request is difficult. What would you implement?

13. - [ ] Traffic suddenly increases 10x. What would you check before simply adding more servers?

14. - [ ] Application works perfectly in staging but fails in production. What differences would you compare?

15. - [ ] A service crashes only under heavy load. How would you identify the actual root cause?

16. - [ ] If you have 2 master servers, one in Pune and one in Bangalore. How do you replicate data?

17. - [ ] If user is added to the Pune server, next request of user goes to Bangalore server. How do you handle this?

18. - [ ] If application is deployed in Pune but user in Brazil facing latency up to 20 seconds. How do you handle it?

19. - [ ] Debugging of code snippet.

20. - [ ] If DB table has 1 million records, you want to add a new field. How will you approach this?
